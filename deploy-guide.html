☑ 本项目的代码已在本机（含 kb/text 知识库、app.py、render.yaml 等）

💡 Key 已经帮你配置在本地 .env 里了。部署时只需把这两个 Key 填进 Render 的环境变量（下文第 4 步）。

1把代码推到 GitHub

Render 通过读取你的 GitHub 仓库来部署。在本机项目目录下执行：

# 首次：在 GitHub 网页新建一个空仓库（不要勾选 README），复制其地址
git remote add origin https://github.com/你的用户名/你的仓库名.git
git add -A
git commit -m "新员工培训AI助手 初始版本"
git push -u origin main
⚠️ .env 已被 .gitignore 忽略，不会被推到 GitHub，Key 不会泄露。

2Render 注册并新建服务

  • 打开 render.com → 用 GitHub 账号注册/登录（免费）。
  • 右上角 New → 选 Blueprint（蓝print 会自动读取仓库里的 render.yaml 配置）。
✅ 选 Blueprint 最省事：它会照着 render.yaml 自动建好 Python 服务、启动命令、端口。

3连接 GitHub 仓库

在 Blueprint 页面点击 Connect 授权 Render 访问 GitHub，然后选择你刚 push 的仓库。Render 会读取 render.yaml 并预览将要创建的服务。

若列表里看不到仓库，确认第 1 步已成功 push，并给 Render 授权了正确的 GitHub 账号。

5点击 Deploy

页面底部点 Apply / Deploy。Render 会拉取代码、安装 requirements.txt 里的依赖、启动服务。首次部署约 1–3 分钟。

⏳ 免费版有"冷启动"：闲置一段时间后首次打开会慢约 30–50 秒，属正常现象，之后就快了。

6拿到链接，发到新员工群

🔄 知识库怎么保持最新（重要）

你在 workbuddy 资料库「新员工培训」里更新了文档，助手怎么跟上？

⚠️ 关键限制：资料库 API 的访问凭证是会话级、约 30 分钟过期的 token，无法在 Render 后端做"无人值守的永久自动同步"。因此采用更可靠的 Git 自动重部署 方案：

标准流程（推荐）——在能打开本 WorkBuddy 助手的对话里，直接说"同步一下资料库"，我会：

# 1) 用当前会话的有效 token 拉取最新资料并抽取
python kb/sync.py --token <当前token>
# 2) 提交并推送（Render 会自动重新部署）
git add kb/text && git commit -m "同步资料库" && git push

Render 检测到新提交会自动重建部署，员工刷新页面即看到最新知识库——这就是"资料更新助手自动跟上"的实现方式。

💡 也可以在本地手动运行上面的命令。只要 kb/text 更新并 push，线上就会自动更新，不需要改代码或重启服务。

🛠 本地试用 / 故障排查

  • 本地启动：python app.py，手机连同一 WiFi 访问 http://你电脑内网IP:8000。
  • 更新知识库后免重启：POST 一下 /api/reload 即可热重载。
  • 回答空白/报错：检查 Render 环境变量 DEEPSEEK_API_KEY 是否填对（health 接口 key:false 即未生效）。
  • 联网核验偶发失效：免费搜索在云服务器 IP 上可能被反爬，建议配好 SerpAPI Key；失败时助手会提示"未联网核验"，不会编造。
  • 员工只能问、看不到全部资料原文：当前前端只展示回答与来源标题，不暴露完整内部文档，符合新人查询场景。
